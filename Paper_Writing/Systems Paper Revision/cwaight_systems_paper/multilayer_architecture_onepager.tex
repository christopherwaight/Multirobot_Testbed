\begin{center}
{\large\bfseries Multilayer Control Architecture}\\[2pt]
{\small C. Waight and C. A. Kitts, Robotic Systems Laboratory, Santa Clara University}
\end{center}

The multirobot system control architecture chosen is an established multilayer approach successfully demonstrated in prior cluster space control studies in both 2D \cite{5,8,10} and 3D \cite{7,9} environments. The three-layer structure, including the feature estimation block of the adaptive navigation layer, follows \cite{5,8}, and the cluster space controller follows \cite{50}. There are three primary layers: (1) an adaptive navigation layer that implements the critical point estimation and adaptive navigation control laws, generating desired cluster centroid velocities, $\dot{\mathbf{p}}_c$, (2) a cluster space controller that maintains formation geometry and translates between cluster space and robot space variables, (3) individual robot controllers that convert velocity commands into mechanical actuation of each robot's drive system. Fig.~\ref{fig:arch} illustrates this hierarchical structure. The architecture itself is not a contribution of this work. This paper provides one estimation function that fills the feature estimation block, and two controllers, attraction and orbit, that fill the navigation controller block and are built to use that estimate. The vector field measurements enter the architecture only at the adaptive navigation layer, which uses them to form the critical point estimate; the lower layers operate on velocity commands alone, without reference to the field.

At each control cycle (10~Hz), each robot reports its position and vector field measurement. The cluster space kinematics are computed, and the cluster shape velocity commands needed for formation control are determined. The adaptive navigation layer computes the critical point estimate and generates a cluster velocity command. The cluster space controller maps all velocity commands to individual robot velocities via the inverse kinematic Jacobian.

\textbf{Robot Controller Layer.} Each robot's controller receives velocity commands and translates them into motion. Each robot also samples the local vector field $\mathbf{v}(\mathbf{p}_i) = (u_i, v_i)$ and reports its global position $\mathbf{p}_i$, providing the inputs to the estimation framework. In simulation, each robot is modeled as a holonomic point with a first-order velocity lag, a speed limit, and Coulomb friction. While robot $i$ moves, its velocity $\boldsymbol{\nu}_i$ follows its command $\boldsymbol{\nu}_{\text{des},i}$ as $\tau\,\dot{\boldsymbol{\nu}}_i = \boldsymbol{\nu}_{\text{des},i} - \boldsymbol{\nu}_i - v_c\,\boldsymbol{\nu}_i/\|\boldsymbol{\nu}_i\|$ with $\|\boldsymbol{\nu}_i\| \le v_{\max}$, where $\tau = 0.28$~s is the actuator time constant measured on the Decabots, $v_c = 0.025$~m/s is the friction level expressed as a speed, and $v_{\max} = 0.4$~m/s is the Decabot top speed. A parked robot stays parked while $\|\boldsymbol{\nu}_{\text{des},i}\| \le v_c$. Commands are held over each 0.1~s control period, and the model is applied in its exact sampled form with $\alpha = e^{-\Delta t/\tau} = 0.70$. The hardware controller also limits the commanded centroid velocity to 0.3~m/s per axis. The sensed field does not appear as a force or drift term, so each robot's velocity responds only to its command.

\textbf{Cluster Space Controller Layer.} The cluster space controller maintains the cluster's formation geometry while executing centroid velocity commands from the adaptive navigation layer. It translates cluster-level velocity commands into individual robot velocity commands using an inverse kinematic Jacobian, and transforms robot position data back into cluster variables for feedback control. In this study, we consider a cluster of three robots forming a triangular configuration. The shape can be parameterized using Side-Angle-Side (SAS) representation with parameters $(p, \beta, q)$, where $p$ is the distance between robots 1 and 2, $\beta$ is the interior angle at robot 2, and $q$ is the distance between robots 2 and 3, as visualized in Fig.~\ref{fig:arch}.

\textbf{Adaptive Navigation Layer.} The adaptive navigation layer is the highest level of the control architecture. It specifies cluster mobility and shape based on real time sensor data from each robot using three functional blocks. A feature estimation block computes the critical point estimate $\hat{\mathbf{p}}^* = -\hat{\mathbf{J}}^{-1}\hat{\mathbf{h}}$ using robot positions and vector field measurements, a navigation controller generates desired centroid velocity commands $\dot{\mathbf{p}}_c$ using either the attraction law $\dot{\mathbf{p}}_c = k(\hat{\mathbf{p}}^* - \mathbf{p}_c)$ or the orbital law $\dot{\mathbf{p}}_c = k_t \mathbf{t} + k_r(r - r_d)\mathbf{n}$, and a formation controller regulates the cluster shape variables $(p, \beta, q)$ to desired values using proportional error feedback. The first two blocks are the contributions of this paper; the formation controller is standard. The navigation and formation velocity commands are combined into a complete cluster-space velocity vector, which is passed to the cluster space controller layer for transformation into individual robot commands.
